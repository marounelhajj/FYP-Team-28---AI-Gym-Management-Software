# Sprint 2 demo script

Fitness Zone, FYP Group 28 (AUB EECE 501). Sprint 2 ran 14 to 28 October 2026 (Jira sprint 68, project SCRUM).

The video is recorded by `demo/record-sprint2-demo.js` from this script. Keep the two in step: the story order, the role
and the click path below are exactly what the recorder does.

## How to produce the video

```bash
npm install                 # once, at the repo root (installs Playwright)
npm run demo:seed           # clean demo database + random logins (demo/.data/, git-ignored)
npm run demo:record         # records everything -> demo/sprint2-demo.mp4 (+ .webm)
npm run demo:record -- --headed   # same, but you can watch the browser
```

Needs `backend/.venv` (see SETUP.md), Google Chrome and `ffmpeg` on the PATH. Ports 4000 and 5173 must be free.
The demo uses its own SQLite file (`GYM_DB_PATH`), so your dev database is never touched.

- **Format:** 1280x720, `slowMo` 400 ms, a visible cursor with a click ripple, **no audio**.
- **Captions:** every story shows its Jira key, title and the role in use, with one sentence held on screen for at
  least 3 seconds.
- **Cards:** a title card at the start, a summary card listing the stories at the end. A story that fails is skipped,
  named on the summary card in red and in `demo/.data/recording-report.json`. Nothing is faked.
- **Logins:** random passwords (and, for staff, an already enrolled authenticator secret) are generated by the seed and
  written only to `demo/.data/credentials.json`. No credentials live in committed files.

## Seeded data (what the story relies on)

Two main branches, **Hamra** and **Jnah** (plus a few members at Achrafieh and Zalka), 57 members, about 190 payments
across the last five months, about 2,000 check-ins over the last four weeks (a daily rhythm that peaks at 6-8 am and
5-8 pm, so the hourly chart and the same-weekday average have data), a handful of members inside right now, 55 retail
sales, rent / payroll / utilities expenses for this and last month, a freeze and cancellation history, and audit
entries. Named members the script uses: **Sami Daher** (lapsed subscription), **Nour Mansour** (active, check-in
target), **Dana Aoun** (lost card), **Lea Haddad** (member login), **Karim Saad** (member login for the deletion).

## 1. System Administrator

### SCRUM-124 Sensitive actions are written to a permanent audit log
- **Click path:** Audit Log tab, point at the first row, click it to expand.
- **Caption:** Every sign-in, edit, payment and cancellation is recorded automatically: who did it, what, when and where.
- **Expected:** a table of entries (When, User, Action, What happened, Branch); the expanded row shows the details.

### SCRUM-125 Search and filter the audit log
- **Click path:** Action select > "Membership cancelled", Branch select > "Hamra", Clear, type "Dana" in the user box, Clear.
- **Caption:** To investigate an incident, filter by action type, branch, user and date range.
- **Expected:** the table narrows to Hamra's cancellations; the user box narrows by name; Clear restores the full list.

### SCRUM-126 Export a filtered audit log as CSV
- **Click path:** Branch select > "Jnah", Export CSV, then Clear.
- **Caption:** The filtered view can be exported as a CSV file to share as evidence in a dispute or review.
- **Expected:** a CSV downloads and a banner reads "Downloaded N entries as CSV. The export itself was added to the log."

### SCRUM-73 Check-ins and cancellations logged as AI training data
- **Click path:** open `/api/training-events?format=json&limit=6` (there is no screen for this story, it is a data log).
- **Caption:** From the first release, every check-in and cancellation is stored as a training event for the future AI models.
- **Expected:** JSON with `total` and `results`: event type, time, branch, member id, no names, emails or phone numbers.

Log out.
