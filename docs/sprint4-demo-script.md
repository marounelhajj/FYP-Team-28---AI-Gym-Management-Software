# Sprint 4 demo script

Fitness Zone, FYP Group 28 (AUB EECE 501). Sprint 4 (Jira sprint 102) runs from 11 to 25 November 2026. The sprint
delivers the at-risk members feature: a weekly, ranked, explained and capped call list of members likely to leave, and
a log of what happened on each call.

The video is recorded by `demo/record-sprint4-demo.js` from this script. Keep the two in step: the order, the role and
the click path below are what the recorder does.

## How to produce the video

```bash
npm install            # once, at the repo root (Playwright)
npm run demo:seed      # fresh demo database + random logins (demo/.data/, git-ignored)
npm run demo:record    # -> demo/sprint4-demo.mp4 (H.264, silent) and demo/sprint4-demo.webm
npm run demo:record -- --headed      # watch it record
npm run demo:record -- --only=gm     # one part while debugging (bm, gm, rec, bm2)
```

Requirements:

- `backend/.venv`, Google Chrome, and `ffmpeg` on the PATH.
- Ports 4000 and 5173 free.
- The demo runs on its own SQLite file (`GYM_DB_PATH`), never your dev database.

Other seeds and recordings:

- `npm run demo:seed` runs `seed_demo_sprint4`, which includes the Sprint 2 and Sprint 3 data. It takes about two
  minutes, because it trains Hamra's model for each past week.
- The Sprint 3 video is `npm run demo:record:sprint3` (it needs `DEMO_SEED=seed_demo_sprint3 npm run demo:seed`).

Recording rules:

- **Format:** 1280x720, `slowMo` 400 ms, a visible cursor with a click ripple, and **no audio**.
- **Captions:** each story shows its Jira key, title and the role in use, with one sentence held for at least 3 seconds.
- **Cards and length:** a title card first ("Fitness Zone, Sprint 4 Demo, FYP Group 28") and a summary card listing the
  stories last. About 4 to 5 minutes.
- **Failures:** a step that fails skips its story. The story is named in red on the summary card and in
  `demo/.data/recording-report.json`. Nothing is faked.
- **Logins:** every staff account gets a random password and an already-enrolled authenticator. Both are generated by
  the seed and written only to `demo/.data/credentials.json`. No credentials are committed.

## Notes for the presenter

- The model's validation numbers come from the seeded history, which is synthetic. Present them as a demonstration of
  the pipeline, not as a result on real gym data.
- "Cancelled anyway" records what the member said on the call. Cancelling the membership is still done from the member
  record.
